Put your team online.

1. Create a home for progress and screenshots

Sign in to Supabase. Choose New project, select your organization, enter a project name and choose a database password. Keep that password in your password manager. Wait until the project is ready.

Open SQL Editor → New query. Open the database setup SQL, copy its entire contents into the editor, and click Run. Success creates two tables: lab_rooms and lab_evidence. They have no public read or write access.

2. Import the website into Vercel

Open Import BIG_DATA_PROJECT on Vercel and choose your team. If needed, connect GitHub and select UjwalSanikam/BIG_DATA_PROJECT. Use the repository root, Framework Preset Other, build command node scripts/build.mjs, and output directory dist. Use Node.js 22 or 24.

3. Add three private server settings

Before deploying, expand Environment Variables in Vercel. Add each name below with its value. For an existing project, use Settings → Environment Variables, select Production, and redeploy after saving.

SUPABASE_URL — copy your project URL from Supabase’s Connect dialog or API settings. It looks like https://your-project.supabase.co.

SUPABASE_SERVICE_ROLE_KEY — copy the project’s server-side service_role key from Supabase Project Settings → API Keys → Legacy API Keys, or use a server secret key. Never use a publishable/anon key here. Never paste a server secret into this website, a screenshot, GitHub or group chat.

LAB_CREATE_KEY — choose a long random passphrase using your password manager. The workspace creator enters this value once when creating the room. Other teammates do not need it.

Click Deploy. Open the production URL. If it says storage is unconfigured, check the variable names and redeploy. If room creation says storage failed, check the SQL migration, project URL and server key.

4. Invite your three teammates

Create one workspace, download the owner recovery key and keep it private. Click Invite team and send that link to the other three people. Each person chooses one different VM and saves their own recovery key.

Save the ZeroTier network ID in Team settings. Everyone confirms their Ubuntu setup and joins the same network. The network owner authorizes all four devices; then enter their assigned IP addresses. Each VM now gets its own commands. Red means wait for the named teammate.

Quick sharing checkOpen the invitation in a different browser profile. Claim a different VM. The first browser should display the new member within a few seconds. Do this on your production URL, not localhost.
